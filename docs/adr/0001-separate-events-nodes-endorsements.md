# ADR 0001：分离对话事件、思想节点与用户确认

## 状态

已接受。

## 决策

`conversation_events` 记录发生过的用户、AI、确认、纠正和拒绝行为；`thought_nodes` 只记录有思想语义的表达；`thought_edges` 连接不同节点。AI 候选保持 system 来源，用户接受或修订创建新的 user 节点，并通过 `provenance_node_id` 与语义边关联。

## 原因

把 AI 问题直接当作可接受观点，或把 AI 节点原地改成用户节点，会丢失来源、用户意图和思想演化。独立事件还允许停止生成、拒绝候选和导出完整过程，而不污染思想图。

## 后果

确认流程多写一个用户节点和一条边，但来源可追溯、导出准确，也能防止接受/拒绝自环。普通问题可以只作为事件，或创建不可确认的开放问题节点。
